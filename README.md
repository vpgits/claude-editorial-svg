# editorial-svg

A Claude Code skill that draws **editorial illustrations for articles** — blog
thumbnails, post covers, OG images — as small, sparse, hand-feeling SVG.

![Four illustrations generated by the skill](docs/examples.png)

> Unofficial and not affiliated with Anthropic. It is a house style built with
> the primitives below, not a copy of anyone's assets.

## What it actually does

The hard part of an article illustration is not the drawing. It is deciding
**what the fewest marks are that make the idea obvious** — and that is exactly
the step a model skips when you ask it for an SVG. You get a competent picture
of a noun, and the piece says nothing.

So this skill spends most of its words on the decision before the code:

| Article | Weak (literal noun) | Strong (mechanism) |
| --- | --- | --- |
| Agents coordinate badly | four robots at a laptop | a handoff chain that visibly weakens at each hop |
| AI art you can still edit | robot holding a paintbrush | a curve with its Bézier anchors and handles exposed |
| Rate limiting a form | a form with an error toast | a crowd meeting a funnel, one mark through |
| Draft previews | a screenshot of the CMS | a stack of versions, one being looked at |

Those four rows are the four images at the top of this page.

Once the abstraction is settled, the drawing is handled by a small library of
composition verbs — `blob`, `gesture`, `arrow`, `node`, `panel`, `hand`,
`cursor`, `cluster` — so output lands in one consistent visual system instead of
drifting into generic clip-art. A hard budget keeps it honest: **7 objects, 4
colours, 3 stroke weights, no text, must survive 160×160.**

## Install

**As a plugin** (one command, updates with `/plugin update`):

```
/plugin marketplace add vpgits/claude-editorial-svg
/plugin install editorial-svg
```

**As a plain skill** — copy the skill directory into your personal skills folder,
or into a project's `.claude/skills/` to commit it with the repo:

```bash
git clone https://github.com/vpgits/claude-editorial-svg
cp -R claude-editorial-svg/skills/editorial-svg ~/.claude/skills/
```

Restart Claude Code either way.

## Use

Ask for artwork in plain language — "make a thumbnail for this post", "draw
something for the rate-limiting article" — and the skill triggers on its own. It
will read the piece, propose the abstraction, write the source, render it, and
look at the result at thumbnail size before calling it done.

The first illustration in a project needs a one-time setup, which the skill runs
for you:

```bash
node <skill>/scripts/vendor.ts art/editorial-svg
```

That copies the library into your repo. It is ~35kb of dependency-free
TypeScript with no build step, so it belongs in the project the way a shadcn
component does — which means every committed illustration still builds for a
collaborator, or in CI, whether or not this skill is installed.

After that, an illustration is a file:

```ts
// art/thumbnails/agent-handoff.ts
import { createIllustration, onField } from '../editorial-svg/index.ts'

export default function build(): string {
  const s = createIllustration({ seed: 4821, palette: onField('sage') })

  s.blob({ x: 508, y: 512, width: 760, height: 700 })      // the carrier
  s.arrow({ from: [230, 348], to: [434, 452], bow: -46 })
  s.dot(230, 348, { radius: 46, fill: s.palette.accent })

  return s.toSVG()
}
```

```bash
node art/editorial-svg/build.ts art/thumbnails
open art/thumbnails/preview.html
```

The build writes a `.svg` beside each source and a preview page that shows every
illustration **at full size, 160px, and 64px** — because an illustration that
only works zoomed in is not a thumbnail.

## Determinism

`seed` fixes every random choice, so the same source always renders
byte-identical output. Change the seed to reroll the hand-drawn wobble without
touching the composition; keep it once you like the result. Both the `.ts` and
the `.svg` are meant to be committed.

For a whole blog, `fieldForKey(slug)` and `seedFromKey(slug)` derive a stable
field colour and seed from a post slug — so an archive page gets varied but
consistent artwork, and regenerating never reshuffles it.

The output is ordinary SVG paths, so anything you don't like is editable
afterwards in Figma or Illustrator.

## The visual system

Four colour roles, never more: one **field** flooding the canvas, one **paper**
carrier the drawing sits on, near-black **ink** for every line, and one **accent**
that appears once or twice. Ink is never pure `#000` — pure black reads as
printer output rather than drawing.

Nine field colours ship: `sage` `clay` `sand` `sky` `ochre` `mist` `rose`
`slate` `charcoal`. Only the field changes between them, which is what makes a
run of posts feel like a set.

## What's in here

```
skills/editorial-svg/
├── SKILL.md              the workflow, constraints, and quality bar
├── lib/                  the drawing library — no dependencies
│   ├── scene.ts          primitives and SVG emission
│   ├── palette.ts        colour roles, fields, slug-derived selection
│   ├── geometry.ts       curves, blobs, resampling, wobble
│   └── random.ts         seeded RNG and noise
├── scripts/
│   ├── build.ts          render a directory of sources + preview page
│   └── vendor.ts         copy the library into a project
├── examples/             four worked illustrations, one per grammar,
│                         each with a header note on what it rejected
└── reference/
    ├── grammar.md        canvas, carrier, stroke language, composition
    ├── primitives.md     every primitive and its options
    └── concepts.md       the concept playbook and failure modes
```

## Requirements

Node **22.18+** — the library is TypeScript run directly by Node's native type
stripping, which is unflagged from that version on. No install step, no
dependencies, no bundler.

## Contributing

New primitives are welcome if they are composition verbs rather than shapes, and
if they earn their place against the existing set. Read
`skills/editorial-svg/reference/grammar.md` first — the system's value is that it
is small.

```bash
npm run examples    # rebuild the example SVGs
npm run validate    # check the plugin and skill manifests
```
